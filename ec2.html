EC2: virtual servers, SSH, firewalls and user data

Instance types, key pairs and how SSH login really works, security groups, a server that builds its own website at boot, and what stop, start and terminate do to your disk, IPs and bill.

By @usmanrangrez · Nov 2026 · Account IDs, IPs and keys in examples are placeholders

Follows M Prashant's AWS in One Video at 1:20:35. The text and labs are my own write-up, not a transcript.

01

What EC2 is

EC2 rents virtual machines (instances) by the second. Each instance is built from:

Piece What it is Analogy
AMI Starting image: OS + software Installation disk
Instance type CPU + memory, e.g. t3.micro Laptop model
EBS volume Its disk The SSD
Security group Firewall Front door lock
Key pair How you log in over SSH House key
Subnet / AZ Where it runs Which building

Reading t3.micro: t = family (burstable, cheap), 3 = generation, micro = size. t4g = Graviton (AWS's ARM chip), which needs an ARM AMI.

bash
aws ec2 describe-instance-types --instance-types t3.micro t3.small t4g.micro m7i.large \
  --query "InstanceTypes[].{Type:InstanceType,vCPU:VCpuInfo.DefaultVCpus,MemoryMiB:MemoryInfo.SizeInMiB,Arch:ProcessorInfo.SupportedArchitectures[0]}" --output table

All four had 2 vCPU; memory 1–8 GiB; only t4g was arm64. The t family is burstable: low baseline, saves CPU credits to burst briefly.

Pricing: pay per second while running. Stopped = no compute charge, but the disk is still billed. Terminated = gone.

02

Key pairs and how SSH login really works

A key pair is two linked keys. The public key can be shared and goes on the server; the private key (.pem) stays only with you. You can derive the public key from the private one (ssh-keygen -y -f key.pem), never the other way round.

LAB · CONSOLE + MAC TERMINAL
  1. EC2 → Key pairs → Create: name my-ec2-key, type ED25519, format .pem.
  2. mv ~/Downloads/my-ec2-key.pem ~/.ssh/ and chmod 400 ~/.ssh/my-ec2-key.pem (SSH refuses keys others can read).
  3. Launch: Amazon Linux 2023 (x86), t3.micro, key my-ec2-key, new security group allowing SSH from My IP, default 8 GiB gp3 disk.
  4. ssh -i ~/.ssh/my-ec2-key.pem ec2-user@PUBLIC-IP (user ec2-user on Amazon Linux, ubuntu on Ubuntu). Type yes at the fingerprint question.
  5. Proof: cat ~/.ssh/authorized_keys on the server matched ssh-keygen -y -f ~/.ssh/my-ec2-key.pem on the Mac.

The login handshake: the client names its public key → the server checks authorized_keys → sends a random challenge → the client signs it with the private key → the server verifies the signature with the public key. The private key never leaves your laptop. Matching public keys alone would prove nothing, because public keys are public; the signature is the proof. The .pem file also contains the public key, which is why ssh-keygen -y prints it instantly.

The "Are you sure you want to continue connecting?" prompt is the other direction: the server's host key, remembered in ~/.ssh/known_hosts. Lose your private key and AWS can't give it back; recover via EC2 Instance Connect or Session Manager.

On the server: hostname shows the private IP name; free -h showed 913 Mi on a 1 GiB instance (the kernel reserves some); df -h / showed the 8 GiB disk. Ghostty users: export TERM=xterm-256color, or permanently printf 'Host *\n SetEnv TERM=xterm-256color\n' >> ~/.ssh/config.

03

Security groups

A security group is a list of "who may connect, on which port".

Fact Meaning
Inbound blocked by default You only add allow rules
Outbound allowed by default The server can reach the internet
Allow rules only No deny rules (use network ACLs for that)
Stateful Replies to allowed traffic go out automatically
Changes apply in seconds No restart; the SG sits in front of the server
Source can be another SG db-sg: 5432 from web-sg, the main production pattern

CIDR: /32 = exactly one IP; /24 = 256; /16 = 65,536; 0.0.0.0/0 = the whole internet. Smaller number after the slash = bigger range.

Timeout vs refused (from nc -vz IP 22 with the rule removed): timeout = something silently dropped the packet → check the security group. Refused = you reached the machine but nothing listens on that port (or it's still booting).

04

User data: a server that sets itself up

User data is a script EC2 runs once, at first boot, as root, via cloud-init. Log: /var/log/cloud-init-output.log.

bash
#!/bin/bash
dnf install -y nginx
echo "<h1>Hello from $(hostname)</h1>" > /usr/share/nginx/html/index.html
systemctl enable --now nginx
Line Does
#!/bin/bash Run with bash (must be line 1)
dnf install -y nginx Install the nginx web server (-y = no questions)
echo … > …/index.html Write the page; $(hostname) inserts the command's output
systemctl enable --now nginx Start now and at every boot

Launched my-web-server with SSH from My IP + HTTP (port 80) from anywhere. The page loaded at http://PUBLIC-IP without anyone logging in. systemctl status nginx showed active (running), enabled, 1 master + 2 workers (2 vCPU); cloud-init finished 36 s after boot. In companies, Auto Scaling launches servers that configure themselves this way; teams often bake most software into a custom AMI and keep user data small.

05

Stop, start, terminate and IPs

Thing After stop → start Why
Disk and files Kept The disk stays attached
Installed programs Kept They're on the disk
Private IP Same Belongs to the network interface
Public IP New Borrowed from AWS's pool, returned on stop
User data Doesn't run again First boot only
Auto public IP Elastic IP Private IP
After stop/start Changes Stays Stays
Internet-reachable Yes Yes No
Costs Small hourly charge Charged even when unattached No

Elastic IP = allocate (reserve for your account) + associate (attach to a server). Attaching it replaces the auto IP. At work, users usually reach a load balancer via a domain name instead.

Terminate: the root disk is deleted (Delete on termination = Yes), but an Elastic IP is not released: release it yourself. Termination protection prevents accidents.

06

How DevOps engineers launch servers

Mostly through Infrastructure as Code (Terraform, CloudFormation) in a pipeline, or Auto Scaling from a template. The CLI is for quick tasks and checks; the console for exploring and debugging.

07

Interview questions

How does SSH key authentication work?

The server stores the public key in authorized_keys, sends a challenge, and verifies the client's signature made with the private key. The private key never leaves the client.

Security group vs NACL?

Security groups are stateful, allow-only and attached to instances (network interfaces). NACLs are stateless, support allow and deny, and apply to whole subnets.

Connection timeout vs connection refused?

Timeout: packets dropped, usually a security group/NACL/routing problem. Refused: host reachable but nothing listening on the port.

What happens to an instance's public IP on stop/start, and how do you keep it?

It changes. Use an Elastic IP, or better, put a load balancer and DNS name in front.

When does user data run?

Once, at first boot, as root, via cloud-init. Check /var/log/cloud-init-output.log.
