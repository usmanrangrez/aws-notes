AWS Notes / Chapter 02

AWS CLI: control AWS from the terminal, with no stored keys

Install the CLI on a Mac, log in with temporary credentials using aws login, find out which identity you are, shape output with --query, and audit and clean an account from the terminal. Includes a real surprise: an old access key from another account hiding on my laptop.

By @usmanrangrez · Nov 2026 · Account IDs, IPs and keys in examples are placeholders

Follows M Prashant's AWS in One Video at 1:09:00. The text and labs are my own write-up, not a transcript.

01

What the CLI is

The console is the website; the CLI does the same things with typed commands. Every command has the same shape:

bash
aws <service> <action> [options]
aws s3 ls
aws ec2 describe-instances

DevOps engineers use it because it's faster than clicking, it goes into scripts, and pipelines run it.

02

How the CLI proves who you are

Way How Safe?
Old: access keys aws configure → paste AKIA… key + secret, saved in ~/.aws/credentials forever ✗ Same risk as any leaked key
New: aws login Opens the browser, you sign in as your IAM user, the CLI gets temporary keys ✓ Nothing permanent on disk

aws login (AWS CLI 2.32.0 or newer, released Nov 2025) refreshes its temporary credentials automatically for up to 12 hours. After that you run aws login again; aws logout ends it early. Older tutorials (from before Nov 2025) show the access-key method.

03

Lab: install and log in

LAB · MAC TERMINAL
  1. Install: download and run https://awscli.amazonaws.com/AWSCLIV2.pkg, then check aws --version (2.32.0 or newer).
  2. aws login → region eu-central-1 → sign in as your admin user in the browser (never root).
  3. aws sts get-caller-identity → should show your own account and user/my-admin.

Why user/my-admin and not assumed-role/…? aws login gives you temporary keys, the same way your console session does. You only see assumed-role/… when you're wearing a role.

04

The surprise: someone else's key on my laptop

My first get-caller-identity returned a different account and a user I didn't create. An old access key was sitting in ~/.aws/credentials from years ago, and the CLI uses the first credentials it finds, so the stored key beat my new login.

bash
aws configure list                         # TYPE column shows where credentials come from
aws configure list-profiles
env | grep '^AWS_' | cut -d= -f1           # names of AWS variables, not values
rm ~/.aws/credentials                      # removed the stray key
aws configure list                         # TYPE now says: login

Never cat ~/.aws/credentials into a chat or ticket: it contains the full secret. Deleting the file only removes the key from the laptop; the key still works in its account until someone there deactivates it.

Debugging rule: wrong identity → aws sts get-caller-identity (who am I) + aws configure list (where do my credentials come from).

05

Output, queries, regions, profiles

Tool Example Does
--output table · text · json Format (json is the default and best for long output)
--query --query "Regions[].RegionName" Pick only the fields you need
--region aws s3 ls --region us-east-1 Another region for one command
--profile aws login --profile work Several identities side by side
help aws ec2 help Built-in manual (q quits)

aws ec2 describe-regions showed 17 regions, not all 39: newer regions are opt-in and hidden until enabled (--all-regions shows them).

Settings live in ~/.aws/config (region, output, login session, no secrets). Permanent keys live in ~/.aws/credentials (secret). With aws login you don't need the second file at all.

06

Lab: audit and clean an account from the terminal

bash
aws iam list-users --query "Users[].UserName" --output text
aws iam list-roles --query "Roles[?starts_with(RoleName,'lab')].RoleName" --output text
aws iam list-open-id-connect-providers --output text
aws iam list-policies --scope Local --query "Policies[].PolicyName" --output text
aws ec2 describe-instances --query "Reservations[].Instances[].[InstanceId,State.Name]" --output text
aws ec2 describe-security-groups --query "SecurityGroups[].GroupName" --output text
aws s3 ls
aws s3 ls s3://BUCKET            # look inside before deleting
aws s3 rb s3://BUCKET --force    # empty + delete the bucket (no undo)

The audit found one forgotten S3 bucket from the IAM labs; rb --force removed it.

07

Interview questions

How should a developer authenticate the CLI on a laptop?

With short-lived credentials: `aws login` (console credentials) or `aws configure sso` (IAM Identity Center). Long-lived access keys only when nothing else is possible.

The CLI acts as the wrong identity. How do you debug it?

`aws sts get-caller-identity` shows who you are; `aws configure list` shows where the credentials come from (environment variables, credentials file, login, SSO…). The first source found wins.

What does --query do?

Filters the JSON response on the client side with JMESPath, e.g. `--query "Reservations[].Instances[].InstanceId"`.
