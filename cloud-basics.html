Cloud & AWS Basics: From Virtualization to Your First Account

Before IAM, EC2 or anything else, it helps to know what the cloud actually is underneath: virtual machines on someone else's hardware, rented by the second. This chapter covers virtualization, cloud computing, how AWS is organised around the world, and how to open an account safely.

01

Virtualization

Virtualization lets one physical computer act like many separate computers. A thin layer of software called a hypervisor splits the real CPU, memory, disk and network into slices, and each slice runs its own operating system as a virtual machine (VM).

Without it, one server runs one OS and one app, often using 10–20% of its capacity. With it, the same server runs ten isolated VMs for ten different customers. That's the economic trick the whole cloud is built on.

Two types of hypervisor

Type 1 (bare-metal)Type 2 (hosted)
Runs onThe hardware directlyAn existing OS
PerformanceNear-nativeSlower (extra OS layer)
Used forData centres, the cloudLearning, testing on a laptop
ExamplesVMware ESXi, Hyper-V, KVM, Xen, AWS NitroVirtualBox, VMware Workstation
Where this shows up in AWS

Every EC2 instance is a VM. Modern instances run on the AWS Nitro System, a lightweight Type 1 hypervisor helped by dedicated hardware cards, so almost all of the server's power goes to your VM. When you pick an instance type like t3.micro, you're choosing the size of your slice.

VMs vs containers

Virtual machineContainer
IsolatesA whole OS (own kernel)Just the app and its libraries (shares the host kernel)
SizeGBsMBs
Starts inTens of seconds to minutesSeconds or less
IsolationStrongerLighter
On AWSEC2ECS, EKS, Fargate (later chapters)

In practice they're combined: containers usually run inside VMs.

02

Cloud computing

Cloud computing is renting computing (servers, storage, databases, networking, software) over the internet, on demand, and paying only for what you use. Instead of buying servers, you create them with a click or an API call and delete them when you're done.

Own data centre vs cloud

Own data centre (on-premises)Cloud
Getting a serverOrder hardware, wait weeksMinutes, from the console or code
PayingBig upfront purchase (CapEx)Pay as you go (OpEx)
CapacityGuess peak demand, often over-buyScale up and down with demand
Going globalBuild in each countryPick another region
MaintenanceYou fix power, cooling, disksThe provider does

The five essential characteristics (NIST definition)

On-demand self-service

You create resources yourself, with no ticket or phone call.

Broad network access

Reachable over the internet from anywhere.

Resource pooling

Many customers share the same hardware, safely isolated (virtualization).

Rapid elasticity

Scale out at peak, scale in at night.

Measured service

Usage is metered, so you pay per second, GB or request.

Service models: who manages what

ModelYou getAWS examplesEveryday example
IaaSRaw servers, disks, networks; you manage the OS and upEC2, EBS, VPCRenting an empty flat
PaaSA platform: you bring code, it runs itElastic Beanstalk, Lambda, RDS (managed DB)Serviced apartment
SaaSFinished software you just useAmazon Connect (contact centre)Hotel room (Gmail, Slack, Zoom)

Lambda is often called FaaS (functions as a service) or "serverless": a PaaS where you don't even see a server.

Deployment models

ModelWhat it isTypical reason
Public cloudShared provider infrastructure (AWS, Azure, Google Cloud)Speed, scale, no hardware
Private cloudCloud-style tooling on your own hardware (e.g. OpenStack, VMware)Strict control or regulation

03

What is AWS?

Amazon Web Services (AWS) is Amazon's public cloud and the largest cloud provider. It started selling cloud services to the public in 2006 (S3 storage and EC2 servers) and now offers more than 200 services. You'll use maybe 20 of them regularly as a DevOps engineer.

Global infrastructure: Regions, AZs and edge locations

PieceWhat it isWhy it matters
RegionA geographic area with its own independent set of data centres, e.g. eu-central-1 (Frankfurt), us-east-1 (N. Virginia)Latency to users, data residency laws (e.g. GDPR), prices and service availability differ per region
Availability Zone (AZ)One or more data centres with separate power, cooling and network; a region has at least three, e.g. eu-central-1aSpread servers across AZs so one building's failure doesn't take you down (high availability)
Edge locationSmall sites in many citiesCache content close to users (CloudFront) and answer DNS fast (Route 53)

As of November 2026, AWS lists 39 Regions with 123 Availability Zones, and more are announced. Numbers change often; check the live map.

How to choose a region

1. Law/compliance: where must the data live? 2. Latency: close to your users. 3. Services: not every service is in every region. 4. Price: varies by region. For learning, pick the nearest one and stay there. These notes use Frankfurt.

A few services are global, not regional: IAM, Route 53 and CloudFront, for example.

The shared responsibility model

AWS is responsible for security of the cloudYou are responsible for security in the cloud
Physical data centres, guards, hardwareWho can access what (IAM)
The hypervisor and the global networkYour OS patches (on EC2), firewall rules (security groups)
Managed-service internals (e.g. the RDS database engine host)Your data: encryption, backups, public/private settings

The more managed the service (PaaS/SaaS), the more AWS takes on. Most AWS security incidents are on the customer side: open buckets, leaked keys, too-broad permissions. That's why the next chapter is IAM.

04 · Lab

Lab: Open an AWS account safely

Free plan or Paid plan?

New accounts choose a plan at sign-up. Both get $100 in credits, and you can earn up to $100 more by completing activities in the first 6 months.

Free planPaid plan
Can you be charged?No, neverYes, pay-as-you-go after credits
EndsAfter 6 months or when credits run out; the account closes (data kept 90 days, so you can upgrade)Doesn't close
ServicesMost; some enterprise services require upgradingAll
Best forLearning (this guide)Real projects
Things that silently upgrade a Free plan to Paid

For example joining or creating AWS Organizations or setting up Control Tower. You can't go back to Free afterwards, and on the Paid plan resources you forget will cost real money.

LAB 0 · BROWSER
  1. Go to aws.amazon.com/free → Create an AWS account.
  2. Enter an email you'll keep long-term (this becomes the root user) and an account name.
  3. Verify the email, set a long unique password, and choose Free plan.
  4. Enter contact details and a payment card. On the Free plan the card is for identity verification, not billing.
  5. Verify your phone number, then choose the Basic (free) support plan.
  6. Sign in as root and immediately do IAM Lab 1: MFA on root, your own admin user, billing access.
  7. Pick your region in the top-right selector (e.g. Europe (Frankfurt)) and keep it for everything.
  8. Check Billing and Cost Management → Credits to see your credit balance and end date.

Optional: look at regions and AZs from the command line

After IAM Lab 1, open CloudShell (the >_ icon at the top of the console) as your admin user:

bash
# every region your account can use
aws ec2 describe-regions --query "Regions[].RegionName" --output text

# the AZs in your current region
aws ec2 describe-availability-zones --query "AvailabilityZones[].ZoneName" --output text
Safe-account checklist

MFA on root · root used only for emergencies · your own admin user with MFA · one region · on a Paid plan, a budget alert (Billing → Budgets → Zero spend budget). The IAM chapter walks through every one of these.

05

Interview Q&A

What is virtualization, and what's a hypervisor?

Running many isolated virtual machines on one physical machine. The hypervisor is the software layer that divides the hardware between VMs. Type 1 runs on bare metal (ESXi, KVM, Nitro); Type 2 runs on top of an OS (VirtualBox).

VM vs container?

A VM virtualizes hardware and runs a full OS with its own kernel; a container virtualizes the OS and shares the host kernel, so it's smaller and starts faster but is less isolated. Containers usually run inside VMs.

What is cloud computing?

On-demand delivery of IT resources over the internet with pay-as-you-go pricing. NIST's five characteristics: on-demand self-service, broad network access, resource pooling, rapid elasticity, measured service.

IaaS vs PaaS vs SaaS, with AWS examples?

IaaS gives raw infrastructure and you manage the OS and up (EC2). PaaS runs your code on a managed platform (Elastic Beanstalk, Lambda, RDS). SaaS is finished software (Amazon Connect, or Gmail outside AWS).

CapEx vs OpEx?

CapEx is buying assets upfront (servers); OpEx is ongoing operating spend (cloud bills). The cloud turns infrastructure from CapEx into OpEx and removes capacity guessing.

Region vs Availability Zone vs edge location?

A region is an independent geographic area; an AZ is one or more isolated data centres inside a region (at least three per region); edge locations are small city sites used by CloudFront and Route 53 to serve users with low latency.

How do you make an app highly available on AWS?

Run it in at least two (ideally three) AZs behind a load balancer, with data replicated across AZs. For disaster recovery, add a second region.

How do you choose a region?

Compliance and data residency first, then latency to users, service availability, and price.

Explain the shared responsibility model.

AWS secures the cloud itself (facilities, hardware, hypervisor, network); the customer secures what they put in it (IAM, data, encryption, OS patching on EC2, network rules). The split shifts toward AWS for more managed services.

On-Demand vs Reserved/Savings Plans vs Spot?

On-Demand: no commitment, highest price. Savings Plans/Reserved: 1–3 year commitment, large discount for steady loads. Spot: deepest discount, can be interrupted with 2 minutes' notice, for fault-tolerant work.
